# Кластер VictoriaMetrics для двух ЦОД

## Архитектура

Конфигурация реализует отказоустойчивый кластер VictoriaMetrics, развернутый на двух ЦОД (две виртуальные машины), обеспечивающий:

1. **Высокую доступность**: при падении одного из ЦОД инфраструктура остается работоспособной
2. **Репликацию данных**: все метрики реплицируются между ЦОД с фактором репликации 2
3. **Общую видимость**: данные по метрикам доступны и видимы из обоих ЦОД
4. **Сохранение исторических данных**: при падении одного из ЦОД все исторические метрики остаются доступны

## Компоненты

- `vminsert`: компонент для вставки метрик, работает в обоих ЦОД
- `vmselect`: компонент для выборки метрик, работает в обоих ЦОД  
- `vmstorage`: компонент для хранения метрик, работает в обоих ЦОД
- Репликация данных обеспечивается параметром `-replicationFactor=2`

## Порты

- vminsert (ЦОД1): порт 8480
- vminsert (ЦОД2): порт 8481
- vmselect (ЦОД1): порт 8481
- vmselect (ЦОД2): порт 8482
- vmstorage (ЦОД1): порты 8400, 8401, 8482
- vmstorage (ЦОД2): порты 9400, 9401, 9482

## Запуск

```bash
docker-compose up -d
```

## Масштабирование

Для развертывания в двух разных ЦОД:
1. Скопируйте `docker-compose.yml` на обе виртуальные машины
2. Убедитесь, что между ними есть сетевая связность
3. Откройте необходимые порты для взаимодействия между компонентами
4. Запустите контейнеры на обеих машинах

## Использование

Для отправки метрик можно использовать любой из vminsert узлов:
- http://host-cod1:8480/insert/0/prometheus/
- http://host-cod2:8480/insert/0/prometheus/

Для запросов метрик можно использовать любой из vmselect узлов:
- http://host-cod1:8481/select/0/prometheus/
- http://host-cod2:8481/select/0/prometheus/
